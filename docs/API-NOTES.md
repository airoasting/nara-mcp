# API 실측 노트

공공데이터포털 조달청 API가 공식 문서에 없거나 문서와 다르게 동작한 내용입니다(2026-11-22 실호출 기준). nara-mcp의 코드는 이 규칙에 맞춰 작성했습니다. 공지(조회 기간, 엔드포인트 버전)가 바뀌면 `g2b_core.py`의 `SERVICES`, `MAX_DAYS`와 이 문서를 함께 고칩니다.

## 공통

1. **입찰공고 서비스는 `ad/BidPublicInfoService02`이고, 오퍼레이션 이름 끝에 `02`가 붙습니다.** `02`가 없는 주소는 같은 키로 `30 등록되지 않은 서비스키`를 돌려줍니다. 낙찰정보 서비스는 공식 swagger 기준 `as/ScsbidInfoService`이며 접미사가 없습니다(`02`를 붙이면 `12`).
2. **조회 기간은 날짜 기준 7일(양끝 포함)까지입니다.** 11/16 00:00~11/22 19:17은 조회되고 11/15 23:59~11/22는 `07`입니다. 2026-11-10 공지로 모든 오퍼레이션에 적용됐습니다.
3. **`01 APPLICATION_ERROR`는 간헐적으로 발생합니다.** 주로 응답이 5초가량 걸릴 때 나며, 같은 요청을 다시 보내면 성공합니다.
4. **개발계정 호출 한도는 서비스마다 하루 1,000건입니다**(공공데이터포털 표기).

## 입찰공고정보서비스

5. **면허 제한·참가 지역·첨부·기초금액을 조회하려면 공고번호와 차수가 모두 필요합니다.** 하나라도 빠지면 `08 필수값 입력 에러`가 납니다.
6. **공고의 업무 구분과 같은 오퍼레이션으로만 조회됩니다.** 용역 공고를 물품 오퍼레이션으로 조회하면 0건입니다.
7. **면허 제한 그룹 사이는 '또는', 그룹 안 항목은 '그리고' 관계입니다.** 의료기기 공고는 제조(그룹 1), 수입(그룹 2), 판매(그룹 3) 중 하나만 충족하면 됩니다. `permsnIndstrytyList`는 해당 항목을 대신할 수 있는 허용 업종입니다.
8. **정정공고는 대개 새 차수로 등록되며, 이때 변경이력 오퍼레이션에는 기록이 없습니다.** 검색 결과에는 같은 공고의 여러 차수가 따로 나오므로 최신 차수만 남겨야 합니다.
9. **취소공고도 마감일이 미래로 남아 있습니다.** 11/20 용역 공고 873건 중 82건(9.4%)이 취소공고였습니다. `ntceKindNm`으로 걸러야 합니다.
10. **조달청 대행 공고의 실제 제안요청서는 e발주 첨부(`getBidPblancListInfoEorderAtchFileInfo`)에만 있습니다.** 필드 이름은 `eorderDocDivNm`, `eorderAtchFileNm`, `eorderAtchFileUrl`입니다. 다른 공고번호가 이름에 붙은 첨부가 섞여 오는 경우도 있었습니다.
11. **첨부 링크(g2b.go.kr)는 로그인 없이 내려받을 수 있습니다.** HWPX는 표 셀 문단이 바깥 문단의 run 아래에 중첩돼, 모든 하위 텍스트를 모으면 표 내용이 두 번 나옵니다.
12. **참가 가능 지역에 `전남광주통합특별시` 같은 새 지역명이 나옵니다.** 시도 약칭 접두어로 맞추면 '전남'에 잘못 걸립니다.
13. **공고 응답에 실무 필드가 들어 있습니다.** `sucsfbidLwltRate`(낙찰하한율), `techAbltEvlRt`/`bidPrceEvlRt`(기술:가격), `cmmnSpldmdMethdNm`(공동수급 방식), `bidQlfctRgstDt`(자격등록 마감), `arsltCmptYn`(실적제한), `dsgntCmptYn`(지명경쟁), `prdctClsfcLmtYn`(세부품명 제한), `jntcontrctDutyRgnNm1~3`(지역의무공동도급), `bfSpecRgstNo`(사전규격 번호).

## 낙찰정보서비스

14. **조회 구분 코드가 오퍼레이션마다 다릅니다**(참고문서 1.2 기준, 실호출로 확인).

| 오퍼레이션 | 조회 구분 |
|---|---|
| 낙찰 목록 `getScsbidListSttus{업무}` | 1 등록일시, 2 공고일시, 3 개찰일시, 4 공고번호 |
| 개찰 결과 `getOpengResultListInfo{업무}` | 1 입력일시, 2 공고일시, 3 개찰일시, 4 공고번호 |
| 검색조건 `…PPSSrch` | 1 공고일시, 2 개찰일시, 3 공고번호 |
| 예비가격 `…PreparPcDetail` | 1 입력일시, 2 공고번호(+차수) |
| 개찰완료·유찰·재입찰 `OpengCompt`, `Failing`, `Rebid` | 조회 구분 없음. 공고번호 필수 |

15. **개찰업체 정보(`opengCorpInfo`)는 `업체명^사업자번호^대표자^투찰금액^투찰률` 형식의 문자열입니다.**
16. **수의계약 공고는 복수예비가격이 1건이고 기초금액이 비어 있습니다.**
17. **단독(참가 1개사) 낙찰이 많습니다.** 용역 113건 중 58건이 단독이었고, 섞으면 낙찰률 중앙값이 크게 오릅니다. 협상에 의한 계약은 투찰률이 0이나 빈 값으로 오는 경우가 많습니다.
