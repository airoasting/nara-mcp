WHY

하루 873건, 사람이 다 열어 볼 수 없습니다

2026년 11월 20일 하루에 올라온 나라장터 용역 공고만 873건이었습니다. 공고마다 면허제한과 참가지역을 열어 보고, HWP 제안요청서를 내려받아 읽어야 합니다. AI에게 맡기려고 API를 붙여 보니 세 군데서 막혔습니다.

조회기간 7일

2026-11-10 공지로 한 번에 1개월에서 7일로 줄었습니다. 그것도 날짜 기준 7일(양끝 포함)이라 하루만 넘어도 07 오류가 납니다.

엔드포인트 버전

새 인증키는 BidPublicInfoService02에만 등록됩니다. 02가 없는 주소는 같은 키로 30 등록되지 않은 서비스키를 돌려줍니다.

HWP 첨부

제안요청서는 대부분 HWP입니다. PDF 변환본은 2026 년, ( 부가세 별도 )처럼 띄어쓰기가 깨져, HWP를 직접 읽어야 원문에 가깝습니다.

WHAT'S DIFFERENT

찾기에서 끝나지 않습니다

깃허브의 나라장터 MCP 다섯 개를 살펴보고 좋은 아이디어는 가져오고, 무거운 부분은 덜어 냈습니다.

01

말하는 대로 찾습니다

"이번 주", "최근 30일", "5억", "3천만원"을 그대로 받습니다. 키워드 여러 개, 제외 키워드, 마감임박·금액순 정렬. 7일 한도는 서버가 최대 5구간(약 35일)으로 나눠 조회합니다.

02

첨부 본문까지 읽습니다

HWP, HWPX, PDF, DOCX, XLSX, ZIP. 제안요청서 → 과업지시서 → 공고문 순으로 고르고, 같은 문서면 HWP를 먼저 읽습니다. 긴 문서는 이어 읽습니다.

03

들어갈 수 있는지 규칙으로 판정합니다

회사 프로필을 한 번 저장하면 마감, 면허·업종, 참가지역, 금액대를 맞대 봅니다. 면허 그룹은 '또는', 그룹 안은 '그리고', 허용업종은 대체 인정. 애매하면 '확인 필요'로 남깁니다.

04

새 공고를 놓치지 않습니다

관심 검색을 저장하면 지난 확인 이후 새 공고만 돌려줍니다. 프로필 기반 추천은 상위 공고를 적합도까지 판정해 '참가 가능'을 위로 올립니다.

05

비슷한 사업은 얼마에, 누가 가져갔는지

낙찰정보서비스로 낙찰률·낙찰금액·참가업체 수의 분포와 자주 낙찰받은 업체를 냅니다. 공고 하나의 투찰 순위, 예정가격, 추첨된 예비가격 4개, 유찰 사유도 봅니다. 하루 1,000건 한도 안에서 버티도록 5분 캐시와 재시도를 둡니다.

INSTALL

4단계, 5분

uvdocs.astral.sh/uv. 파이썬과 의존성을 알아서 맞춥니다.
입찰공고정보서비스 인증키공공데이터포털에서 활용신청. 개발계정은 자동승인입니다.
낙찰정보서비스 (선택)낙찰 도구를 쓰려면 같은 키로 신청합니다.
1

저장소 받기

git clone https://github.com/airoasting/nara-mcp.git ~/nara-mcp
2

인증키 넣기

인증키 자리에 발급받은 값을 넣습니다.

printf 'G2B_SERVICE_KEY=인증키\n' > ~/nara-mcp/.env && chmod 600 ~/nara-mcp/.env
3

Claude Code에 등록

의존성은 첫 실행 때 uv가 설치합니다.

claude mcp add nara -s user -- uv run --directory ~/nara-mcp python server.py
4

확인

Claude Code를 새로 열고 /mcp에서 nara가 연결됐는지 봅니다. Claude 데스크탑 앱 설정은 README에 있습니다.

LIMITS

이것은 입찰 자문이 아닙니다

공개된 제한만 봅니다. 중소기업 제한, 실적 제한, 공동수급, 직접생산 확인은 공고문으로 따로 확인합니다.
낙찰 도구는 명세 기준입니다. 공식 swagger와 참고문서 1.2대로 만들고 샘플 응답 형태로 시험했습니다. 실서비스 응답 검증은 진행 중입니다.
읽지 못하는 첨부가 있습니다. 암호 HWP, 배포용 HWP(미리보기만), 스캔 이미지 PDF(OCR 없음).
긴 기간은 약 35일까지입니다. 그보다 오래된 공고는 공고번호로 직접 조회합니다.
